# Разметка открытых комментариев пульса

Текущая версия инструкции и схемы — **1.0.0**. [Инструкция и словарь категорий](v1/instructions.md) · [Схема JSON](v1/schema.json).

## Вход и подготовка

Модуль сверяет `data/processed/comments.csv` с `data/raw/comments.csv` по ID, тексту и номеру логической записи. Реестр сотрудников помогает установить наличие автора. Точный текст получает SHA-256 от его UTF-8-представления. Пробелы и регистр сохраняются. Даты, идентификаторы сотрудников, команды и другая информация о строке в запрос модели не входят.

В `data/processed/comment_analysis/` записываются перечень текстов, связь с каждым `comment_id`, контрольные суммы входов и пустая таблица для независимой разметки. Пустые строки и явные заглушки сохраняются со статусом качества. Короткие содержательные ответы остаются кандидатами для модели. Записи с отсутствующим или неподтверждённым автором сохраняются, а `usable_team_text` для них равно `false`.

```powershell
uv run --no-sync python -m src.pulse_comments prepare
```

Для новой волны сначала проверьте входные файлы и выполните `prepare --inventory-only`. Параметры пути ставятся перед подкомандой. `--comments` задаёт обработанные комментарии, `--raw-comments` их исходник, `--employees` реестр, `--output` каталог результата. Сформируйте новый список из 30 SHA-256 и передайте его через `--sample-ids`. Версия 1.0.0 содержит фиксированную [выборку текущей выгрузки](v1/review_sample_ids.json).

## Независимая ручная проверка

1. Команда `prepare` создает `data/processed/comment_analysis/manual_review_template_v2.csv`. Для новой ручной проверки скопируйте шаблон под отдельным именем. Импортируйте файл как UTF-8 с разделителем `;` и сохраните значения `text_id` и `text` в точности. В репозитории уже есть [заполненная контрольная выборка исследования](../../data/processed/comment_analysis/manual_review_filled.csv).
2. Для строки «Нет комментариев.» укажите `placeholder` в `gold_status`. Оставьте все остальные `gold_*` пустыми.
3. Для остальных 29 строк укажите `substantive` в `gold_status` и заполните категории по словарю. Несколько категорий в одном поле разделяйте `|`. В `gold_evidence` укажите точный фрагмент, в `gold_quit_evidence` — фрагмент только при наличии сигнала об уходе. `reviewer_note` можно оставить пустым.
4. Завершите ручную разметку до запуска модели. Отбор целевой и включает распространённые и редкие формулировки, нейтральные сообщения, заглушку и примеры с несколькими темами или возможной неоднозначностью. Таблица скрывает частоты, принадлежность к группам и предполагаемые метки.

```powershell
uv run --no-sync python -m src.pulse_comments validate-review --review data/processed/comment_analysis/manual_review_filled.csv
```

После появления `comment_labels.jsonl` выполните локальное сопоставление. Оно учитывает каждый текст один раз. Для заглушки отдельно проверяется, что все связанные записи имеют статус `placeholder` и пустую метку модели. Точность тональности, совпадение тем, полнота обнаружения высоких и критических проблем и ложные сигналы ухода рассчитываются на 29 содержательных текстах после получения всех их меток.

```powershell
uv run --no-sync python -m src.pulse_comments evaluate --review data/processed/comment_analysis/manual_review_filled.csv
```

Результаты этой выборки характеризуют знакомые шаблоны. Для оценки новых формулировок соберите независимую выборку. Разбирайте неоднозначные случаи по исходным фрагментам. После изменения инструкции сохраните первичную разметку, создайте новую версию и отделите тексты для настройки от независимой проверки.

## Запуск Gemini после ручной проверки

Модель по умолчанию — [Gemini 3.5 Flash-Lite](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite), ID `gemini-3.5-flash-lite`. На 21 ноября 2026 года Google указывает бесплатные стандартные текстовые запросы в пределах Free Tier. Тариф Paid Tier в таблице Google составляет $0,30 за миллион входных токенов и $2,50 за миллион выходных токенов, включая токены рассуждения. Бесплатный режим может использовать переданные данные для улучшения продуктов Google. Используйте синтетический набор. Для реальных HR-текстов сначала согласуйте обработку и передачу данных. [Тарифы Google](https://aistudio.google.com/docs/pricing#gemini-3.5-flash-lite).

Ключ создаётся в [Google AI Studio](https://aistudio.google.com/api-keys). Проверьте у проекта статус Free Tier, доступность региона и проектные лимиты RPM, TPM, RPD. Приложение не определяет тариф по ключу. Флаг `--confirm-free-tier` означает, что оператор проверил проект в AI Studio. Подписка Gemini Pro и доступ Gemini Developer API управляются отдельно. [Тариф проекта](https://aistudio.google.com/docs/billing) · [Лимиты проекта](https://aistudio.google.com/rate-limit) · [Доступные регионы](https://aistudio.google.com/docs/available-regions).

```powershell
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'Gemini API key' -AsSecureString)).Password
uv run --no-sync python -m src.pulse_comments classify --review data/processed/comment_analysis/manual_review_filled.csv --confirm-free-tier --rpm 5 --max-texts 5
```

Параметр `--rpm 5` задаёт локальный темп, его следует сверить с лимитом проекта. `--max-texts 5` ограничивает первый проход пятью новыми текстами. После проверки повторите команду с подходящей порцией. Временные ошибки и HTTP 429 обрабатываются ограниченными повторными попытками. Если квота остаётся исчерпанной, перезапустите команду позже.

При ошибке формата модуль делает до двух запросов на исправление с пояснением поля или правила. При блокировке или исчерпании этих попыток текст получает статус `needs_manual_review`, классификатор переходит к следующему тексту. Успешные ответы и записи ручной проверки повторно не отправляются при запуске с тем же кэшем. Сводка по проблемным ID и всем попыткам сохраняется в `manual_review_by_text.jsonl`. Диагностика хранит код и пояснение, без ключа и необработанного ответа API.

Модель возвращает JSON. Модуль проверяет перечисления, типы, дословные фрагменты и правила ручной проверки. Результат сохраняется по хэшу текста, ID модели и хэшу инструкции. Кэш SQLite содержит версию модели из ответа API, версию инструкции и время. После перезапуска сохранённые результаты используются повторно. `labels_by_text.jsonl` содержит размеченные тексты по ключу, `comment_labels.jsonl` — перенос размеченных полей на исходные записи. Статусы `pending`, `placeholder` и `empty` сохраняются без присвоения меток модели.

Исходный ответ модели храните отдельно от последующих человеческих исправлений. При ручном исправлении указывайте текстовый ID, версию исходной метки, изменённые поля, основание и дату. Для анализа используйте только проверенный слой с сохранённым происхождением. При публикации соблюдайте пороги малочисленности. Серьёзность описанной проблемы и вероятность индивидуального ухода имеют разные значения. По разметке не следует принимать кадровые решения о человеке.
