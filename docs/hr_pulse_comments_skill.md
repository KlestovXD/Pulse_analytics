# Навык Codex для новой волны HR-комментариев

Навык [hr-pulse-comments](../.agents/skills/hr-pulse-comments/SKILL.md) доступен в проекте. Откройте корень репозитория в новом диалоге Codex и укажите задачу, вход и разрешённый режим.

> Используй $hr-pulse-comments. Проверь синтетическую волну из `data/incoming/pulse_2027_02/` на дату 2027-02-16. Сохрани её в `data/waves/2027-02/run-v1/`. Подготовь инвентаризацию и отчёт покрытия без отправки данных. Покажи ошибки, которые нужно устранить до классификации.

Для разрешённой классификации дополните запрос указанием рабочего кэша, подтверждением проекта Free Tier и лимитом запросов. Подписка Gemini Pro и ключ Gemini Developer API относятся к разным продуктам. Для рабочих HR-данных требуется согласование способа передачи, хранения и обработки.

## Вход

Четыре файла UTF-8 с разделителем `;` и заголовками из [словаря проекта](Словарь_данных.md). Используйте одну выгрузку на волну.

| Файл | Данные для проверки |
|---|---|
| `comments.csv` | Уникальный `comment_id`, `employee_id`, месяц `wave`, команда, дивизион, дата отправки, исходный текст |
| `employees.csv` | Уникальный сотрудник, команда, дивизион, грейд, формат работы, дата найма, руководитель |
| `survey_responses.csv` | ID записи опроса, сотрудник, волна и дата, существующие поля шкал |
| `exits.csv` | Уволившиеся сотрудники, даты и типы увольнения. При отсутствии событий допустим один заголовок |

`--wave-date` задаёт дату закрытия волны. `wave` в CSV имеет вид `YYYY-MM` и совпадает с её месяцем. Допустимы ответы, отправленные до даты закрытия в том же месяце. При более позднем состоянии реестра укажите `--snapshot-end YYYY-MM-DD`. Используйте полный кадровый срез, необходимый для сверки принадлежности и дат.

## Команды

Из корня репозитория, с установленными через `uv sync` зависимостями:

```powershell
$waveArgs = @('--raw', 'data/incoming/pulse_2027_02', '--wave-date', '2027-02-16', '--output', 'data/waves/2027-02/run-v1')
uv run --no-sync python -m src.pulse_comments.wave @waveArgs prepare
uv run --no-sync python -m src.pulse_comments.wave @waveArgs report
```

Обе команды работают локально. Критические ошибки перечислены в `audit_issues.jsonl`. Для другой выгрузки, даты, модели или инструкции выберите отдельный каталог результата. При повторном запуске для той же выгрузки сохраняйте прежний каталог и рабочий кэш.

Для отправки синтетической выгрузки через одобренный Free Tier проверьте лимит проекта в AI Studio. [Настройка модели и ключа](../prompts/comment_classification/README.md).

```powershell
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'Gemini API key' -AsSecureString)).Password
uv run --no-sync python -m src.pulse_comments.wave @waveArgs classify --cache data/waves/comment_cache.sqlite3 --confirm-free-tier --rpm 5 --max-texts 10
```

Если у вас есть локальная SQLite-копия предыдущей разметки, добавьте `--seed-cache <путь-к-архиву.sqlite3>` при первом запуске. Обычная копия репозитория содержит сохраненные метки исследования в JSONL. Они достаточны для локального воспроизведения аналитики. Следующие волны используют рабочий кэш. Уберите ограничение `--max-texts` при подходящей квоте. Статус и условия оплаты проверьте в проекте AI Studio перед отправкой. Используйте отдельные кэши для имитации и рабочих запусков.

| Результат | Как использовать |
|---|---|
| `audit_issues.jsonl`, `inventory.json`, `unique_texts.csv`, `comment_text_map.csv` | Сверить исходники, пропуски, исключения и уникальные формулировки |
| `labels_by_text.jsonl`, `comment_labels.jsonl` | Сверить версию модели, метку текста и перенос на записи |
| `manual_review_by_text.jsonl`, `manual_followup.csv` | Разобрать технические отказы и метки, требующие содержательной сверки |
| `comment_volume.csv`, `comment_distribution.csv` | Проверить покрытие и доли среди валидно размеченных записей. Малые группы скрыты |
| `wave-summary.md`, `wave-summary.json` | Прочитать краткий результат и сверить контрольные суммы, версии, покрытие и условия сравнения |

При ограничениях квоты или доступе к провайдеру возобновите запуск после их устранения с тем же рабочим кэшем. При исчерпании повторов конкретный текст остаётся без метки в технической очереди. Серьёзные и неоднозначные случаи, указания на уход и промежуточную серьёзность отправляйте на содержательную проверку. Исходную модельную метку сохраняет отдельный слой.

```powershell
uv run --no-sync python -m src.pulse_comments.wave @waveArgs apply-review --review data/waves/2027-02/run-v1/manual_followup_filled.csv
```

Скопируйте `manual_followup.csv` под отдельным именем. Укажите `decision` (`confirm` при подтверждении или `correct` при исправлении), `reviewer` и `reviewed_on` в формате `YYYY-MM-DD`. При исправлении запишите только измененные поля в `corrections_json`, например `{"severity":"высокая"}`, и основание в `review_note`. Сохраните исходные поля дословно. Для текущего исследования используйте `uv run --no-sync python -m src.pulse_dashboard apply-review --review <путь-к-заполненному-CSV>`.

Применённые решения записываются в `reviewed_labels_overlay.jsonl` отдельно от исходных меток. Отчёт по исходной модели ведётся отдельно. Неразмеченные технические случаи остаются в очереди до решения человека и учитываются в покрытии.

Для периодической оценки передайте JSON-массив выбранных `text_id`. Выбирайте тексты по частотам и рискам, включайте новые формулировки. Фиксированный размер выборки не требуется. Для утверждений о качестве нужен файл человеческих оценок.

```powershell
uv run --no-sync python -m src.pulse_comments.wave @waveArgs prepare --sample-ids data/waves/2027-02/control_ids.json
uv run --no-sync python -m src.pulse_comments.wave @waveArgs report --sample-ids data/waves/2027-02/control_ids.json --review data/waves/2027-02/manual_review_filled.csv
```

## Проверка навыка

Синтетическая [выгрузка за февраль 2027 года](../data/fixtures/hr_pulse_comments_wave/) содержит знакомые и новые формулировки, повторные записи, заглушки, неоднозначность и случаи для ручной проверки. Тест подменяет HTTP-транспорт и запускает рабочий код проверки ответа, кэширования, повторных попыток и переноса меток на записи. Метки для теста получены через имитацию API.

Локальный Codex обнаружил навык в каталоге проекта. В сквозном тесте из 18 записей выделено 12 уникальных содержательных текстов. Одна метка получена из тестового кэша, десять прошли валидацию после имитации запроса, один текст направлен на ручную проверку после трёх ошибок формата. Две заглушки и одна пустая запись обработаны локально. Повторный запуск дал те же результаты без запросов. Отдельная проверка подтвердила, что критическая ошибка даты блокирует обработку.

```powershell
uv run --no-sync python -m unittest discover -s tests -p test_comment_wave.py -v
```
